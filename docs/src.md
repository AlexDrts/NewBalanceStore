## 1. Вступ

### 1.1. Мета документа
Цей документ визначає функціональні та нефункціональні вимоги до вебзастосунку **New Balance Store**, який являє собою повноцінну платформу електронної комерції для перегляду, пошуку та придбання товарів бренду New Balance. 

SRS використовується як основний документ для планування, розробки, тестування та подальшого оцінювання програмного продукту.

### 1.2. Обсяг продукту
New Balance Store — це повнофункціональна веб-платформа електронної комерції, що дозволяє користувачам переглядати товари, формувати кошик, оформлювати замовлення з онлайн-оплатою, а адміністраторам — керувати каталогом. Проєкт реалізується як командний проєкт із застосуванням методології Scrum, системи контролю версій Git та архітектури Clean / Onion.

Проєкт має продемонструвати практичне використання сучасних технологій веброзробки, принципів об'єктно-орієнтованого програмування, REST API, роботи з базами даних, автентифікації, авторизації, тестування та командної розробки.

### 1.3. Аудиторія документа
Команда розробників (Backend, Frontend, Full-stack), керівник проєкту, члени комісії з захисту, QA-інженери (в рамках навчального процесу).


### 1.4. Референс
За основу UI та загальної концепції використовується американська версія офіційного сайту New Balance US. Поточний React-проєкт команди базується на попередній реалізації дизайну New Balance, розробленій у межах дисципліни React.


### 1.5. Нормативні посилання та стандарти
При розробці специфікації та проєктуванні системи використовуються такі міжнародні стандарти та регуляції:
* **ISO/IEC/IEEE 29148:2018** — Systems and software engineering — Life cycle processes — Requirements engineering.
* **OWASP Top 10 (2025/2026 Edition)** — Стандарт безпеки вебзастосунків та основних ризиків.
* **GDPR / CCPA Compliance** — Стандарти приватності та захисту персональних даних користувачів.

## 2. Загальний опис

### 2.1. Перспектива продукту
**New Balance Store** розробляється як навчальний e-commerce продукт, архітектурні та UX-рішення якого базуються на кращих практиках сучасних платформ електронної комерції та дизайні офіційного сайту New Balance US. Система складається з клієнтської частини (React SPA), серверної частини (ASP.NET Core Web API) та хмарної платформи Firebase (Cloud Firestore / Authentication).

### 2.2. Класи користувачів та привілеї

| Роль | Опис | Ключові дозволи |
| :--- | :--- | :--- |
| **Гість (Guest)** | Неавторизований відвідувач | Перегляд каталогу, пошук, фільтрація, перегляд деталей товару |
| **Покупець (Customer)** | Авторизований користувач | Функціонал Гість + кошика, оформлення замовлення, історія замовлень, управління профілем |
| **Адміністратор (Admin)** | Менеджер платформи | CRUD товарів |
| **Система (System)** | Автоматизовані процеси | Валідація JWT-токенів, автоматична зміна статусів кошика |

### 2.3. Операційне середовище

| Компонент | Специфікація |
| :--- | :--- |
| **Клієнт** | Браузери Chrome, Firefox, Safari |
| **Сервер** | ASP.NET Core Web API (.NET 8.0+), хостинг на Render / Vercel / Railway |
| **Клієнтський фреймворк** | React 18+, Vite, React Router, CSS Modules |
| **Серверний фреймворк** | ASP.NET Core Web API, Firebase Admin SDK |
| **База даних / Хмара** | Firebase (Cloud Firestore) |
| **Автентифікація** | Firebase Authentication / JWT |
| **Архітектура** | Clean Architecture / Onion Architecture |
| **Мови інтерфейсу** | Англійська (en-US) |

### 2.4. Обмеження дизайну та реалізації

| Шар | Технологія | Обґрунтування |

## 3. Межі проєкту (Scope)

### 3.1. In Scope
* Пошук товарів за назвою
* Детальна сторінка товару
* Реєстрація, авторизація та керування профілем (Firebase Auth / JWT)
* Історія замовлень
* Адміністративна панель (Управління товарами)
* REST API з OpenAPI/Swagger документацією
* База даних Firebase (Cloud Firestore)
* Безкоштовне розгортання (Deployment на Render / Vercel)

### 3.2. Out of Scope
На першому етапі розробки **не реалізується**:
* Нативні мобільні застосунки (iOS / Android)
* Реальна інтеграція з платіжними системами (використовується демо-процесинг)
* Інтеграція з реальними службами доставки (UPS, USPS Delivery)
* Інтеграція з фізичними точками продажу
* Повноцінна ERP/CRM-система
* Мікросервісна інфраструктура

## 4. Функціональні вимоги

### 4.1. Головна сторінка
* **FR-01:** Система повинна відображати головну сторінку, що містить: Головний Header Hero-секцію, рекомендовані товари, рекламні банери та Footer.

### 4.2. Каталог товарів
* **FR-02:** Система повинна відображати перелік товарів у вигляді сітки (Grid). Картка товару повинна містити: назву, зображення, категорію за статтю (Men, Women, Unisex), ціну, доступні розміри.
* **FR-03:** Система повинна надавати детальну сторінку товару, що містить: галерею зображень, назву, опис, ціну, технічні характеристики, вибір розміру та кольору, кнопки «Додати до кошика».

### 4.3. Пошук, фільтрація та сортування
* **FR-04:** Пошук товарів за назвою.
* **FR-05:** Фільтрація товарів за параметрами: категорія, стать (чоловіче, жіноче, unisex), ціновий діапазон, розмір, колір.
* **FR-06:** Сортування товарів: за зростанням ціни, за спаданням ціни, за найновішим товаром, за доступним для покупки товаром.

### 4.4. Автентифікація та авторизація
* **FR-07:** Реєстрація нових користувачів із валідацією полів (Email, Password, Name).
* **FR-08:** Автентифікація існуючих користувачів.
* **FR-09:** Використання JWT (JSON Web Tokens) для збереження сесії та захисту API endpoint'ів.
* **FR-10:** Рольова модель доступу (RBAC): підтримка ролей `Guest`, `Customer` та `Admin`.

### 4.5. Кошик
* **FR-11:** Додавання товарів до кошика з вибором конкретного розміру та кольору.
* **FR-12:** Управління кошиком: зміна кількості одиниць товару, видалення окремих позицій автоматичний перерахунок загальної вартості.

### 4.6. Замовлення (Orders)
* **FR-13:** Оформлення замовлення з можливістю введення: імені, прізвища, Email, телефону, адреси доставки.
* **FR-14:** Створення замовлення у системі з присвоєнням унікального номера та початкового статусу `Pending`.
* **FR-15:** Перегляд історії замовлень у кабінеті користувача (номер, дата, склад замовлення, загальна сума, поточний статус).

### 4.7. Адміністративна панель
* **FR-16:** Доступ до панелі адміністрування виключно для користувачів із роллю `Admin`.
* **FR-17:** Повний цикл CRUD-операцій над товарами (створення, редагування, видалення).


### 4.8. Backend API
* **FR-18:** Взаємодія між Frontend та Backend відбувається через REST API.
* **Маршрути API:**
  * `/api/auth` — реєстрація, логін, оновлення токенів
  * `/api/products` — товари (CRUD, фільтрація, детальні дані)
  * `/api/orders` — створення та перегляд замовлень
  * `/api/users` — управління профілем

## 5. Use Cases

### UC-01: Перегляд товару
* **Актор:** Guest / Customer
* **Сценарій:**
  1. Користувач переходить до каталогу товарів.
  2. Застосовує фільтри за категорією або ціною.
  3. Натискає на картку товару.
  4. Система відображає сторінку товару із фотографіями, описом та сіткою розмірів.

### UC-02: Додавання товару до кошика
* **Актор:** Customer
* **Сценарій:**
  1. Користувач відкриває сторінку товару.
  2. Обирає розмір та колір.
  3. Натискає «Add to Cart».
  4. Backend перевіряє наявність товару та оновлює стан кошика в БД.

### UC-03: Оформлення замовлення
* **Актор:** Customer
* **Сценарій:**
  1. Користувач переходить у кошик і натискає «Checkout».
  2. Вводить контактні дані та адресу доставки.
  3. Підтверджує замовлення.
  4. Система фіксує замовлення зі статусом `Pending` та очищає кошик.
